# 小宇宙 FM 车机客户端 需求文档 v0.1

2026-11-05 · Ryan Xia · 在线版：https://claude.ai/artifact/3q6MyfKXxNBpXXvEaoDwvq

## 背景与目标

目标是做一个个人自用的小宇宙轻量客户端，在比亚迪 DiLink 6.0 车机上完成「登录、听我的订阅、进度和手机互通」。

- **现状**：DiLink 官方应用商店没有小宇宙。侧载官方手机版后，第三方登录（推测是微信 / Apple）在车机上不好用。
- **定位**：轻度封装的客户端，只做听播客的核心链路，接口参考 [ultrazg/xyz](https://github.com/ultrazg/xyz)。
- **约束**：只给本人用，不分发、不商用，只适配本人车辆的 DiLink 6.0。
- **成功标准**：上车后 3 秒内能续播上次的单集；手机上听到哪，车上就从哪接着听，反过来也一样。

## 范围与非目标

v0.1 只做「听」，不做「社交」。

**本版范围**

- 手机号短信登录，登录态长期保持
- 我的订阅、单集列表、播放、进度双向同步
- 发现页、搜索、订阅管理、单集详情、收听历史、播放队列
- 通过安卓标准媒体接口（MediaSession）接入车机：方向盘按键、状态栏和桌面媒体卡片

**非目标**

- 评论、点赞、关注、贴纸等社交功能
- 付费单集、离线下载
- 微信 / Apple 等第三方登录
- 「小迪，播放某某播客」这类语音深度接入：只在 M0 顺带测一下通用语音指令，不作为需求
- 其他车型和系统版本的适配、分发上架、商用

## 运行环境与技术选型

结论：**MyGo 不能在 DiLink 上运行**。已选定方案 A：原生 Kotlin + Media3，接口层参考 ultrazg/xyz 移植。

**运行环境（待实车确认）**

- DiLink 6.0 和 5.1 同属 DiLink 150 这一代（5.1 有人实测是 Android 13），推测 6.0 是 Android 13 或更高
- 最大 15.6 英寸旋转屏，1920×1080，横屏和竖屏都要支持
- 通过 U 盘或 ADB 侧载 APK，签名拦截的情况待验证

**为什么不用 MyGo**

- [MyGo](https://github.com/egoist/mygo) 只有 macOS、Linux、Windows、Web（js/wasm）四个后端。在 Android 上会落到 `backend_other.go` 和 `nowplaying_other.go`，两者都是空实现。
- [mygo-cloudmusic](https://github.com/LeslieYon/mygo-cloudmusic) 是桌面客户端（带刘海播放器），只能借鉴它的工程结构，以及把登录态存在系统凭据里的做法，代码不能复用。
- 把 MyGo 的 Web 版本套进 WebView 里也不行：没有 MediaSession，方向盘按键收不到；WebView 在后台播放音频不可靠。

**候选方案**

| 方案 | 组成 | 优点 | 代价 |
| --- | --- | --- | --- |
| A（已选定）纯 Kotlin | Compose + Media3（ExoPlayer + MediaSessionService）+ OkHttp；参考 xyz 用 Kotlin 重写接口 | 只有一种语言，工具链最简单；P0 只需要约 10 个接口 | xyz 更新后要手动同步 |
| B Go 内核 + Kotlin 外壳 | 用 gomobile 把 xyz 编译成 .aar，UI 和播放器仍用 Kotlin | 直接复用 xyz 的 Go 代码 | 需要 NDK 和 cgo 工具链；Go 和 Kotlin 之间只能传基础类型；要调试两种语言 |

不管选哪个方案，播放器、MediaSession 和 UI 都只能用 Kotlin 写，Go 能承担的只有 HTTP 客户端这一层。所以选定方案 A。

**客户端架构**

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌ ─ ─ ─ ─ ─ ─ ─ ┐
│   界面 UI     │────▶│   数据仓库    │────▶│  API 客户端   │────▶   小宇宙服务端
│ Compose·横竖屏│     │ 缓存·节流·同步│     │ 参考 xyz 移植 │     └ ─ ─ ─ ─ ─ ─ ─ ┘
└──────┬───────┘     └──▲────────┬──┘     └──────┬───────┘
       │播放控制          │上报进度  │读写           │读取 Token
┌──────▼───────┐        │        │        ┌──────▼───────┐
│   播放服务    │────────┘        └───────▶│   本地存储    │
│ Media3·前台服务│                          │Token加密·列表缓存│
└──────▲───────┘                          └──────────────┘
       │MediaSession
┌──────▼──────────────────┐
│ 车机系统：方向盘按键·状态栏·语音 │
└─────────────────────────┘
```

播放服务通过 MediaSession 和车机交换按键与播放状态。小宇宙改接口时，只需要改 API 客户端。

## 车机适配与 UX

核心原则：主要操作一眼看清、一次点中，常用控件放在靠近驾驶位的屏幕左侧和下方。

**设计原则**

1. **靠近驾驶位**：国内是左舵车，屏幕左侧和下方离驾驶员最近。播放控制放在横屏的左侧、竖屏的底部。
2. **少看一眼**：每屏只展示必要信息；列表每屏不超过 6 项；标题最多两行，超出部分截断。
3. **少点一下**：从启动到继续播放只需要 1 次点击；从发现页或订阅列表播放任一单集不超过 3 次点击。
4. **少打字**：搜索优先提供搜索建议、最近搜索和热门搜索，可以直接点选；需要输入时调用车机系统输入法，支持语音输入就直接用。
5. **不依赖精细手势**：不用长按、双击和小号关闭按钮；除了拖动进度条，还提供后退 15 秒 / 前进 30 秒按钮。

**尺寸规范**

参考 [Android for Cars 尺寸规范](https://developers.google.com/cars/design/android-auto/design-system/sizing)。dp 的实际大小取决于屏幕密度，以实车测得的为准。

| 元素 | 规格 |
| --- | --- |
| 最小触控区域 | 76×76dp，相邻触控区域间距 ≥ 16dp |
| 播放 / 暂停按钮 | ≥ 120dp，全界面最大 |
| 后退 / 前进 / 倍速按钮 | ≥ 96dp |
| 进度条 | 可见高度 8dp，触控热区高度 76dp |
| 主文字（单集标题等） | 32dp |
| 次文字（节目名、时长等） | 24dp |
| 文字与背景对比度 | ≥ 4.5:1 |

**布局**

- **横屏**：左侧约 40% 是「正在播放」面板，包含大封面、标题、进度条和播放控制；右侧约 60% 是浏览区，靠近屏幕中间的一侧是竖向导航栏（发现 / 订阅 / 搜索 / 历史），再往右是内容列表。
- **竖屏**：从上到下依次是内容列表、导航栏、「正在播放」面板。播放控制在屏幕最下方，伸手最近。
- **系统区域**：适配 DiLink 的状态栏和底部 Dock，内容不被遮挡。
- **屏幕旋转**：横竖屏切换时保持播放状态和列表滚动位置，不重新加载。播放状态由 Service 持有，界面用 `WindowSizeClass` 切换布局。
- **启动默认页**：订阅。

│┏━━━━━━━━━━━━┓ ┌────┐ ┌───────────────────┐│       │┌────────────────┐│

导航栏紧挨播放面板，内容列表放在离驾驶位最远的位置；每一行右侧的播放按钮可以直接播放该单集。

**交互细节**

- **启动**：「正在播放」面板直接显示上次的单集和进度，点一下播放按钮就能继续听（对应 F7）。
- **倍速**：点一下切到下一档（1.0 → 1.25 → 1.5 → 2.0 → 1.0），不弹出菜单。
- **列表项**：整行都可以点击进入详情；右侧放一个播放按钮，可以直接播放。
- **反馈**：所有按钮都有按下状态；加载时显示骨架屏；网络错误时显示大号提示和「重试」按钮，不用小号 Toast。

**视觉**

- 默认深色主题，跟随车机的昼夜模式切换。
- 风格参考小宇宙：大封面、圆角卡片、简洁的列表，主色取小宇宙的品牌色。只供自用，不涉及素材授权问题。

**系统集成**

- **MediaSession**：用 Media3 `MediaSessionService` 实现方向盘按键、状态栏和桌面媒体卡片，并提供封面、标题、节目名等元数据。方向盘「上一曲 / 下一曲」对应「后退 15 秒 / 前进 30 秒」。
- **音频焦点**：导航播报时自动降低音量，来电时自动暂停，结束后自动恢复。
- **语音**：M0 顺带测试「暂停 / 继续 / 下一首」是否生效，只记录结果，不作为验收条件。
- **开机续播**（可选）：车辆启动后自动恢复上次的播放状态。要先确认车机是否允许第三方应用开机自启。

## 非功能需求

重点是让请求看起来像正常的单用户，以及在弱网环境下不卡顿。

| 类别 | 要求 |
| --- | --- |
| 账号安全 | 只有登录会触发风控（xyz 的 README 有警告），所以尽量减少登录：优先用刷新 token 续期，不自动重试登录；先用小号验证 |
| token 存储 | 存在 EncryptedSharedPreferences 或 Android Keystore 里，不写日志 |
| 请求频率 | 进度每 30 秒最多上报一次；列表缓存 5 分钟；请求头和设备信息参考 xyz，固定不变 |
| 弱网和离线 | 列表和封面缓存在本地，没有网络时可以浏览；播放时预缓冲 ≥ 60 秒；上报失败的进度先存本地，恢复网络后补发 |
| 性能 | 冷启动到可以点击继续播放 ≤ 3 秒；列表滚动保持 60 fps |
| 稳定性 | 播放 Service 以前台服务运行，防止被车机系统杀掉；崩溃日志保存在本地，可以用 ADB 导出 |
| 接口变更 | 接口调用全部集中在一个模块里，小宇宙改接口时只需要改这一处 |

## 验证清单与里程碑

先花 1–2 天做完 M0 实车验证，全部通过再进入开发。

**M0 实车验证**

- [ ] 在「设置 → 系统信息」记录 Android 版本和 DiLink 版本号，据此确定 minSdk 和 targetSdk
- [ ] 用 U 盘装一个自签名的测试 APK，确认没有签名拦截；顺便看能否开启 ADB
- [ ] 侧载官方小宇宙 APK，试一下手机号短信登录。如果能用，重新评估是否还要自己开发
- [ ] 用小号在电脑上跑 xyz：登录、刷新 token、读取和上报进度，观察 3 天是否触发风控
- [ ] 写一个最小的 Media3 demo，测试方向盘按键、桌面媒体卡片、语音「暂停 / 下一首」，以及屏幕旋转时不断播
- [ ] 用 `adb shell wm size` 和 `adb shell wm density` 记录屏幕分辨率和密度，确认 dp 规范的实际大小；量一下状态栏和 Dock 占用的高度

**里程碑**

1. **M0 验证**：完成上面的清单，确定技术方案。
2. **M1 能登录、能播放**：完成 F1–F5 和 F8，在车上能听订阅的节目。
3. **M2 日常可用**：完成 F6、F7 进度同步和续播，横屏和竖屏布局完整，开始自己长期使用。
4. **M3 发现与浏览**：完成 P1 的 F9–F14，本版功能全部交付。

## 待确认问题与风险

**待确认**

- 「三方登录不好用」具体是什么现象？如果官方 APK 用手机号短信登录就能解决，自己开发的必要性会下降。
- DiLink 6.0 的 Android 版本、是否有签名拦截、是否允许开机自启。

**风险**

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 登录触发风控或封号 | 主账号不可用 | 先用小号验证；尽量用刷新 token 代替重新登录 |
| 小宇宙修改接口或加签名 | 客户端失效 | 关注 xyz 的更新；接口层集中在一个模块，改动成本低 |
| 车机 OTA 后收紧侧载 | 无法安装或更新 | 保留已安装的版本；升级 OTA 前先看车主社区的反馈 |
| 开启 ADB 受限 | 调试效率低 | 改用 U 盘安装，日志写入文件后导出 |
